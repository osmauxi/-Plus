# 玩家同步脚本阅读顺序

## 先看懂这些术语和代码名

| 术语 | 含义 |
|---|---|
| Tick（固定模拟步） | 固定频率推进的一次玩家模拟序号 |
| Snapshot（状态快照） | Server 下发的某个 Tick 完整或增量玩家状态 |
| Full / Delta（完整 / 增量快照） | Full 可独立还原；Delta 依赖 Baseline 才能还原 |
| Baseline（基准快照） | 解码 Delta 所依赖的 Full Snapshot |
| Owner（对象拥有者） | 有权为该网络玩家提交输入的 Client |
| Server Authority（服务器权威） | Server 校验输入并决定最终状态 |
| Prediction（本地预测） | Owner 不等网络返回便立即模拟本地输入 |
| Reconcile（权威校正） | 用 Server 状态检查本地预测并决定是否回滚 |
| Rollback / Replay（回滚 / 重演） | 恢复权威旧状态，再执行后续未确认输入 |
| Hard Resync（硬同步） | 缺少可回滚历史时直接跳到权威状态 |
| Exact（精确输入） | 输入 Tick 与下一 Server Tick 完全匹配 |
| RetimedLate（迟到重定时输入） | 窗口内最新迟到输入被改到下一权威 Tick 执行 |
| ReusedPrevious / Hold（沿用上一输入） | 短时缺包时有限次数继续上一输入 |
| Neutral（中立输入） | 不移动、不瞄准、不冲刺的安全输入 |
| Ring Buffer（环形缓冲） | 按 Tick 保存固定数量历史、满后覆盖最旧槽位的容器 |
| Transport（传输层） | 负责序列化、消息发送、接收和对象路由的层 |
| Warp（强制传送） | 复活、换层或服务器强制移动玩家时的同步重置 |
| NGO（Netcode for GameObjects） | Unity 的网络对象、连接、所有权和固定 Tick 框架 |
| UTP（Unity Transport） | NGO 下方实际收发数据并实现 Delivery 管线的传输层 |
| NetworkObjectId（网络对象编号） | NGO 为每个已生成网络对象分配的唯一编号 |
| OwnerClientId（拥有者客户端编号） | 表示哪个 Client 有权提交该对象输入的编号 |
| Named Message（具名消息） | 通过名称注册和路由的 NGO 自定义消息 |
| Delivery（发送模式） | 指定消息是否可靠、是否有序的传输选项 |
| Payload（应用数据净荷） | 同步代码序列化的业务字节，不含底层协议头 |
| Harness（测试编排器） | 自动建立网络、施加弱网、驱动玩家并采集结果的组件 |

核心类型可以先按“一句话作用”记忆：

| 代码名 | 作用 |
|---|---|
| `PlayerSyncConfig` | 所有同步频率、容错窗口、校正阈值和插值参数 |
| `PlayerInputCommand` | 带 Tick 的移动、瞄准和按钮输入结构体 |
| `PlayerSimulationState` | 能完整恢复玩家运动、控制和体力的状态结构体 |
| `PlayerSnapshotPacket` | 表示 Full 或 Delta Snapshot 的网络包结构体 |
| `TickMath` | 安全处理 `uint` Tick 回绕比较的工具 |
| `TickRingBuffer<T>` | 用 Tick 索引输入或状态历史的固定容量容器 |
| `PlayerSimulationClock` | 保存当前 Tick、固定频率和单步时长的纯 C# 时钟 |
| `IPlayerCharacterBody` | 让纯 C# 运动逻辑访问位置、旋转和碰撞移动的身体接口 |
| `CharacterControllerPlayerBody` | 把身体接口适配到 Unity `Transform` 与 `CharacterController` 的普通 C# 类 |
| `PlayerMotor` | 负责速度、转向、重力和位移积分的底层纯 C# 类 |
| `PlayerLocomotionController` | 负责玩法移动状态、体力和 Motor 调用的纯 C# 类 |
| `PlayerSimulation` | 预测端与权威端共用的模拟、状态捕获和恢复入口 |
| `PlayerPrediction` | Owner 的输入历史、本地预测、校正和重演模块 |
| `PlayerServerAuthority` | Server 的输入接收、输入选择和权威模拟模块 |
| `PlayerRemoteInterpolation` | Observer 的快照缓冲与远端表现模块 |
| `PlayerSyncTransport` | 输入/快照网络协议和端点路由模块 |
| `PlayerSyncController` | 按网络身份驱动整条同步链路的总控组件 |

方法名中常见动词：`Push/Submit` 表示送入数据，`Predict/Simulate` 表示推进模拟，`Capture/Restore` 表示捕获/恢复状态，`Reconcile` 表示权威校正，`Replay` 表示重演历史输入，`Reset` 表示清空旧时间轴并建立新起点。

## 逐文件阅读目标

### 1. `Config/PlayerSyncConfig.cs`

先记住系统的时间尺度和容错边界：

- 30 Hz 固定模拟；
- 20 Hz Snapshot（状态快照）；
- 1024 Tick 历史；
- 输入冗余 3；
- Hold（沿用上一输入）3 Tick；
- RetimedLate（迟到重定时）12 Tick；
- Remote 插值延迟 0.1 秒；
- Full（完整快照）之间最多 9 个 Delta（增量快照）。

阅读重点是派生属性：`InputSendIntervalTicks`、`IdleHeartbeatTicks`、`RemoteInterpolationDelayTicks`。`TickDeltaTime`（单步时长）已经迁移到 `PlayerSimulationClock`，避免配置和运行时各自计算一份。

### 2. `Data/PlayerSyncData.cs`

按类型顺序读：

1. `PlayerInputButtons`（定义瞄准、冲刺等输入按钮位）；
2. `PlayerInputCommand`（保存某 Tick 的移动、瞄准和按钮输入）；
3. `PlayerSimulationState`（保存可恢复的完整玩家状态）；
4. `TickMath`（处理 Tick 回绕下的新旧比较和距离）；
5. `PlayerSnapshotPacket`（封装 Full/Delta 快照及变化字段）；
6. `TickRingBuffer<T>`（用固定容量按 Tick 保存历史）。

重点方法：

- `PlayerInputCommand.TrySanitize`（拒绝非法数值并输出范围安全的输入副本）；
- `PlayerInputCommand.WithTick`（复制输入内容并替换其 Tick）；
- `TickMath.IsNewer/Distance`（回绕安全地判断 Tick 新旧、计算 Tick 距离）；
- `PlayerSnapshotPacket.CreateFull/CreateDelta/TryResolve`（创建完整/增量快照，并用 Baseline 还原完整状态）；
- `TickRingBuffer.Store/TryGet/Remove`（按 Tick 写入、读取和移除历史槽位）。

读完应能回答：线上传什么、完整状态是什么、Delta 依赖什么、uint Tick 溢出如何比较。

### 3. `Middle/PlayerSimulationClock.cs`

这是当前最简单的纯 C# 固定步时钟。按以下顺序读：

1. 构造函数：校验 `TickRate`（每秒固定步数）并计算 `TickDeltaTime`（单步秒数）；
2. `Reset`（把时钟重新对齐到 Spawn、Warp 或 Hard Resync 指定的 Tick）；
3. `AdvanceOneTick`（把 `CurrentTick` 向前推进一步，并保持 `uint` 回绕语义）。

它不读取 Unity `Time`，也不订阅 NGO。当前由 `PlayerSyncController.HandleNetworkTick` 收到 `NetworkTickSystem.Tick` 后调用一次。二轮重构可以替换驱动器，但 Prediction 和 ServerAuthority 不需要重新发明 Tick 计数。

### 4. 纯 C# 底层模拟栈

先按持有方向阅读：

1. `../Local/Lower/PlayerCharacterBody.cs`：`IPlayerCharacterBody`（身体访问接口）声明模拟所需的最小 Unity 能力；`CharacterControllerPlayerBody`（CharacterController 身体适配器）实现姿态读取、移动和安全传送；
2. `../Local/Lower/PlayerMotor.cs`：`PlayerMotor` 保存速度、角速度等运行状态，计算加速度、制动、重力与朝向，再调用身体接口移动；
3. `../Local/Middle/PlayerLocomotionController.cs`：`PlayerLocomotionController` 持有 Motor，推进控制状态和体力，并提供统一的捕获、恢复与 Warp（强制传送）入口；
4. `Middle/PlayerSimulation.cs`：`PlayerSimulation` 持有 Locomotion，作为 Prediction（预测）和 Server Authority（服务器权威）的共同门面。

阅读 `PlayerSimulation` 时重点看：

- `Simulate`（用一条输入和固定步长推进一次玩家模拟）；
- `CaptureState`（沿持有链收集一份可回滚状态）；
- `RestoreState`（把位置、速度、控制状态和体力恢复到指定状态）。

读完应能画出：`PlayerSyncController -> PlayerSimulation -> PlayerLocomotionController -> PlayerMotor -> IPlayerCharacterBody -> CharacterController`。前三个模拟类和身体适配器都是普通 C# 类，只有最上层 Controller（总控）和 Unity 原生 CharacterController 需要挂在玩家对象上。

### 5. `Middle/PlayerPrediction.cs`

按以下顺序：

1. `Reset`（清空预测历史并设置新的 Tick 起点）；
2. `Predict`（消费 Controller 时钟已经派发的 Tick、执行本地模拟并保存历史）；
3. `ShouldSend/MarkSent`（判断是否应立即发包，并记录最近已发送输入）；
4. `Reconcile`（比较同 Tick 权威状态，必要时恢复并重演）；
5. `HardResync`（历史不可用时直接恢复到 Server 权威状态）。

重点理解两个 Ring Buffer：Input History 用于 Replay 和冗余发送，State History 用于同 Tick 误差比较。

### 6. `Middle/PlayerServerAuthority.cs`

先读 `PushInput`（净化并按时间分类 Client 输入），再读 `ResolveNextInput`（为下一权威 Tick 按优先级选输入）。

核心顺序：

```text
Sanitize
  -> Future/Outdated/Monotonic 检查
  -> Exact Buffer 或 Pending RetimedLate
  -> 下一 Tick：Exact > RetimedLate > ReusedPrevious > Neutral
```

特别关注：

- `_latestObservedClientTick` 防旧冗余覆盖新输入；
- `_pendingLateSourceTick` 与 `_pendingLateInput`；
- RetimedLate 的 12 Tick 时间窗；
- Exact 到来时如何清除更旧 Pending；
- `MaxInputHoldTicks` 如何避免无限卡键。

### 7. `Middle/PlayerRemoteInterpolation.cs`

按 `PushSnapshot`（把新权威状态放入有序缓冲） -> `TrySample`（为当前表现时间寻找采样结果） -> `Interpolate`（在相邻快照之间计算平滑状态）阅读。

重点理解 `_renderOffset`：它不是直接按本机时间取最新状态，而是保持在最新权威 Tick 后约 3 Tick 的表现时间轴。

同时注意当前没有外推，Buffer 边界会停在 Oldest 或 Latest。

### 8. `Lower/PlayerSyncTransport.cs`

先看生命周期：

- `Initialize`（注册输入和快照消息处理器）；
- `RegisterEndpoint/UnregisterEndpoint`（建立或删除 NetworkObjectId 到玩家同步端点的路由）；
- `Shutdown`（反注册消息并清理端点、Baseline 和指标）。

再看两条协议：

- `SendInputBatch -> OnInputMessageReceived`（Client 批量发送当前/历史输入，Server 接收后校验并路由）；
- `SendSnapshot -> OnSnapshotMessageReceived`（Server 发送权威快照，Client 接收并还原完整状态）。

阅读时重点核对：

- Named Message（具名自定义网络消息）名称；
- Delivery（可靠性与顺序性发送模式）类型；
- NetworkObjectId（网络对象唯一编号）路由；
- OwnerClientId（对象所属客户端编号）校验；
- Full Baseline（完整基准快照）缓存；
- `DroppedDeltaWithoutBaselineCount`（因缺少基准而丢弃的增量快照数）增长条件；
- Payload（应用数据净荷）计数是否只包含应用层 Writer 长度。

### 9. `Upper/PlayerSyncController.cs`

最后读总控，因为它把前面的类按身份拼起来。

建议按方法顺序：

1. `Awake`（创建 Clock、Body、Motor、Locomotion 和 Simulation 的纯 C# 对象图）；
2. `OnNetworkSpawn`（重置初始 Tick，按当前身份创建预测、权威或插值模块并注册端点）；
3. `SubmitLocalInput`（保存 Driver 提交的最新本地输入事实）；
4. `HandleNetworkTick`（先推进纯 C# Clock，再把同一 Tick 交给预测或权威模块）；
5. `RunOwnerPredictionTick/TrySendOwnerInput`（执行 Owner 预测并按发送策略上行输入）；
6. `RunServerTick/TrySendSnapshot/BroadcastSnapshot`（执行权威模拟、构建快照并向 Client 广播）；
7. `ReceiveInputFromClient/ReceiveServerSnapshot`（接收 Transport 路由来的输入或权威状态）；
8. `LateUpdate/UpdateRemotePresentation`（每渲染帧更新 Observer 的平滑表现）；
9. `ResetAfterWarp`（传送后重置时钟、模拟、输入历史、插值和 Baseline）；
10. `OnNetworkDespawn`（取消 Tick 订阅并移除网络端点）。

读完应能画出 Remote Owner、Server、Remote Observer 和 Host Owner 四种身份路径。

## 按链路跟读

### Remote Owner 输入上行

```text
LocalPlayerLocomotionDriver.Update
  -> PlayerSyncController.SubmitLocalInput
  -> HandleNetworkTick
  -> PlayerPrediction.Predict
  -> TrySendOwnerInput
  -> PlayerSyncTransport.SendInputBatch
```

### Server 权威模拟

```text
PlayerSyncTransport.OnInputMessageReceived
  -> PlayerSyncController.ReceiveInputFromClient
  -> PlayerServerAuthority.PushInput
  -> PlayerSyncController.RunServerTick
  -> PlayerServerAuthority.SimulateNextTick
  -> PlayerSimulation.Simulate
```

### Snapshot 下行与 Owner 校正

```text
PlayerSyncController.BroadcastSnapshot
  -> PlayerSnapshotPacket.CreateFull/CreateDelta
  -> PlayerSyncTransport.SendSnapshot
  -> PlayerSyncTransport.OnSnapshotMessageReceived
  -> PlayerSyncController.ReceiveServerSnapshot
  -> PlayerPrediction.Reconcile
  -> Restore + Replay（需要时）
```

### Remote Observer 表现

```text
PlayerSyncController.ReceiveServerSnapshot
  -> PlayerRemoteInterpolation.PushSnapshot
  -> PlayerSyncController.LateUpdate
  -> PlayerRemoteInterpolation.TrySample
  -> PlayerSimulation.RestoreState
```

## 建议断点与指标

### 输入迟到

- `PlayerServerAuthority.PushInput` 的 Outdated 分支；
- `RetimedLateAcceptedInputCount`（被接受为候选的最新迟到输入数）；
- `RetimedLateInputTickCount`（权威 Tick 实际执行迟到重定时输入的次数）；
- `NeutralInputTickCount`（权威 Tick 实际执行中立输入的次数）。

### Owner 抖动或瞬移

- `PlayerPrediction.Reconcile`；
- `NeedsRollback`（判断预测误差是否超过校正阈值）；
- `HardResync`（历史不可用时直接恢复权威状态）；
- `LastPositionError/LastVelocityError`（最近一次位置/速度预测误差）；
- `LastReplayTickCount`（最近一次校正重演的输入 Tick 数）。

### Remote 卡顿

- `PlayerSyncTransport.OnSnapshotMessageReceived` 的 Baseline 检查；
- `DroppedDeltaWithoutBaselineCount`（因缺基准快照而无法解码的 Delta 数）；
- `PlayerRemoteInterpolation.PushSnapshot/TrySample`；
- `RemoteBufferedSnapshots`（Observer 当前插值缓冲中的快照数量）。

### 带宽和发送频率

- `InputPacketSendCount`（Owner 已发送的输入包数量）；
- `SnapshotSendCount/SnapshotReceiveCount`（已发送/接收的状态快照数量）；
- `PlayerSyncTransport.InputPayloadBytesSent`（输入消息应用层累计字节）；
- `PlayerSyncTransport.SnapshotPayloadBytesSent`（快照消息应用层累计字节）。

当前 `PlayerSyncController` 的主循环仍订阅 `NetworkManager.NetworkTickSystem.Tick`（NGO 网络固定步事件），但 Tick 编号和单步时长已经由 `PlayerSimulationClock` 管理。看到 `_snapshotSendRate`、`_inputSendRate` 时，应把它们理解为模拟 Tick 之上的发送额度；独立时间累加、追帧和漂移校正留作二轮重构。

阅读时先确认角色身份和 Tick，再看状态误差。直接从 Transform 表象追查，容易把预测、权威和插值三个不同时间轴混在一起。
