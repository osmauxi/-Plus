# 场景与程序集交收规范

## 1. 固定架构

- Player Build Settings 中必须且只能启用 `Assets/_HotUpdate/Scenes/BootStrapScene.unity`。
- `BootStrapScene` 属于 AOT 启动层，只负责读取热更 DLL、补充 AOT 元数据、初始化热更运行环境并进入首个 Addressable 场景。
- 除 Boot 外，生产场景全部加入 Addressables，使用完整 Asset Path 作为 Address，并添加 `HotUpdateScene` 标签。
- AOT 程序集不得引用 `HotFix.*`。`HotFix.*` 可以引用稳定的 AOT 接口程序集。
- 生产场景上的 `HotFix.*` 组件所属 asmdef 必须加入 `HybridCLR Settings/Hot Update Assembly Definitions`。
- `Assets/_HotUpdate/Scenes/Tests` 下的测试场景也可以进入 Addressables，但测试 asmdef 不加入生产 HotUpdateAssemblies，也不得作为正式流程入口。

## 2. 新程序集接入

1. 在 `_HotUpdate/Scripts` 的合适业务目录创建 asmdef，名称统一为 `HotFix.<Domain>` 或 `HotFix.<Domain>.<Module>`。
2. asmdef 只引用所需的 AOT 接口和其他热更程序集；禁止循环引用，禁止 AOT 反向引用热更程序集。
3. 在 `HybridCLR Settings` 中登记该生产热更 asmdef。
4. 执行 `HybridCLR/Generate/All`，确认生成过程无程序集解析、泛型或桥接函数错误。
5. 执行 `Tools/HotUpdate/Build And Sync DLLs`，确认对应 `.dll.bytes`、`.pdb.bytes` 已同步到 Addressables 使用的目录。
6. 检查 Addressables 的 `HotfixDLLs` 组中存在该 DLL，标签与加载顺序符合 Boot 配置。
7. 如果程序集改名或拆分，必须同时清理：asmdef References、HybridCLR Settings、Addressables 旧 DLL 条目、`link.xml`、Boot 加载名单及 ServerData 中的旧 bundle/catalog。

## 3. 新场景接入 Addressables

1. 场景放在 `Assets/_HotUpdate/Scenes` 下；生产场景不能加入 Player Build Settings。
2. 在 Addressables 的 `Scenes` 组加入场景。
3. Address 必须等于场景完整路径，例如：
   `Assets/_HotUpdate/Scenes/GameRunTimeScene.unity`。
4. 添加 `Scene` 和 `HotUpdateScene` 标签。
5. 场景脚本必须来自已登记的 `HotFix.*` 程序集，或稳定的第三方/AOT 程序集；不得存在 Missing Script。
6. 场景切换统一调用 `GameSceneFlowController`，底层统一走 `NetworkSceneLoadService.LoadAddressableSceneAsync`。禁止对热更场景直接使用 `SceneManager.LoadScene`，也禁止使用 NGO 默认的 Build Settings 场景管线。

## 4. NGO 与 Addressable 场景规则

- `HotFixEntry` 在启动网络前关闭 NGO 默认场景管理：`EnableSceneManagement = false`。
- Lobby 场景加载完成后，必须先调用 `RegisterSceneNetworkObjects`，再允许 `StartHost` 或 `StartClient`。
- 网络切场时，服务端向所有客户端下发 Address；各端通过 Addressables 加载并回执；全部成功后，服务端生成该场景中的 NetworkObject。
- Addressables 独占 Scene/GameObject 生命周期；NGO 只管理 NetworkObject 身份和同步。自定义 Handler 的 `Destroy` 禁止销毁场景对象，真正销毁只能由 `Addressables.UnloadSceneAsync` 完成。
- 卸载顺序固定为 Server `Despawn(false)`、全端进入同一卸载步骤、注销 Handler、Addressables 卸载。禁止直接卸载仍处于 Spawn 状态的场景。
- Addressable 场景中的 NetworkObject 必须具有稳定、非零且互不重复的 `GlobalObjectIdHash/PrefabIdHash`。加载后由自定义 `INetworkPrefabInstanceHandler` 将 NGO 的生成消息绑定到本地已加载的场景对象。
- 当前管线覆盖“大厅中的现有玩家一起进入游戏”。若以后支持玩家在游戏进行中加入，必须增加 late join 场景状态同步和补载流程后再验收。
- 场景 Address 是网络协议的一部分。服务端与客户端必须使用同一 catalog/content 版本，否则会出现加载失败、对象哈希不一致或 RPC 生成失败。

## 5. AOT 与泛型保障

- `LoadMetadataForAOTAssembly` 只补充 AOT 程序集元数据，不能替代 NGO 对热更类型生成的序列化注册代码。
- NGO ILPP 会在热更 DLL 中生成 `__GEN.NetworkVariableSerializationHelper.InitializeSerialization()`。由于热更 DLL 在 Unity 启动后才通过 `Assembly.Load()` 载入，其 `RuntimeInitializeOnLoadMethod` 不会自动回放。
- Boot 必须在每次 `Assembly.Load(bytes)` 后立即、显式调用该程序集的 `InitializeSerialization()`；本项目已在 `BootstrapRunner` 实现。
- 新增 `NetworkVariable<T>`、`NetworkList<T>`、RPC 参数或 `INetworkSerializable` 类型后，必须重新执行 HybridCLR 生成、热更 DLL 同步及 Addressables 构建。
- 若改变 AOT 代码、补充元数据列表、Bootstrap、Unity/NGO/HybridCLR 版本或 Player Build Settings，必须重建 Player；仅更新 ServerData 不够。

## 6. 标准导出顺序

1. 执行 `Tools/Validation/Scene And Assembly Handover`。
2. 执行 `HybridCLR/Generate/All`。
3. 构建 Windows Player，使新的 AOT/裁剪结果进入安装包。
4. 执行 `Tools/HotUpdate/Build And Sync DLLs`。
5. 执行 Addressables `New Build/Default Build Script`。
6. 将新的 `ServerData/StandaloneWindows64` 完整部署到远端目录；不要只覆盖单个 bundle。
7. 确认运行时 Profile 的 RemoteLoadPath 指向实际地址，catalog、hash 和 bundle 可从客户端访问。
8. 若是局域网测试，服务端监听地址使用可达网卡 IP，防火墙同时允许资源端口 TCP 和游戏传输端口 UDP。

## 7. 每次交收验收

- 校验器通过：Build Settings 只有 Boot；生产场景全部 Addressable；无 Missing Script；无未登记热更程序集。
- Boot 日志出现所有 AOT 元数据加载成功、热更 DLL 加载成功及 `[HybridCLR][NGO] 序列化注册完成`。
- 首次启动和清缓存启动都能进入 LobbyScene。
- “直接开始游戏”和“创建房间”两条链路均测试，主机与至少一台局域网客户端均进入 GameRuntime/UI 场景。
- 检查日志不存在：`Serialization has not been generated`、`Missing Script`、`different serialization layout`、Addressables catalog/bundle 404、scene load timeout、重复 `PrefabIdHash`。
- 检查开关代理、切换网卡和 IP 变化后的 RemoteLoadPath；客户端必须访问宿主机局域网 IP，不能使用 `localhost`。
- 保留本次 Player、ServerData、catalog/hash 和 Git 提交号，保证客户端内容版本可追溯。

## 8. 常见报错定位

| 报错/现象 | 优先检查 |
| --- | --- |
| `Serialization has not been generated for T` | 热更 DLL 是否经过 NGO ILPP；`Assembly.Load()` 后是否显式执行 NGO 序列化注册；是否同步了新 DLL |
| 场景大量 Missing Script/serialization layout mismatch | 场景是否仍被内置进旧 Player；热更 DLL、场景 bundle 和 Player 是否来自同一轮构建 |
| Boot 卡住，关代理可进入 Lobby | RemoteLoadPath、代理绕过、catalog/bundle 地址、防火墙和 Hosting 服务监听网卡 |
| 创建房间后网络错误 | UDP 游戏端口、防火墙、监听地址、客户端连接 IP、Transport 配置 |
| Linker 无法解析 `HotFix.*` | AOT 程序集或 `link.xml` 是否错误引用热更程序集；是否残留旧程序集名 |
| 服务端切场成功、客户端失败 | 两端 catalog/content 版本、场景 Address、加载回执和超时日志 |
