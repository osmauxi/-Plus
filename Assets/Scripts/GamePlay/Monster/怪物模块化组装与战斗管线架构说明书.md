- # 怪物模块化组装与战斗管线架构说明书 

  ## 1. 架构总览：三权分立与数据驱动

  本系统摒弃了传统的“庞大单例类（God Class）”继承树，采用 **数据驱动架构**。

  - **配置层 ：** `MonsterDataSO` (数据源) 与 `MonsterEntity` (外壳)。负责提供怪物的出厂数值，并对接发牌员与对象池的生命周期管理。
  - **状态层：** `AIBlackboard`。怪物大脑的唯一记忆体，只存储数据（目标是谁、距离多远、是否正在攻击），绝对不包含任何 `Update` 逻辑。
  - **逻辑层：** `MonsterBrain` 统筹运转，底层驱动三大互相独立的“行为模块”执行具体逻辑。

  ------

  ## 2. 核心行为模块系统：热插拔与底层逻辑

  本架构的最大优势在于**绝对的独立性与热插拔**。所有模块（寻找、移动、攻击）之间**互相不可见**，它们只能通过 `AIBlackboard` 进行读写。这意味着你可以把“近战攻击模块”拔下来，插上“远程射击模块”，这只丧尸瞬间就变成了骷髅弓箭手，且不会产生任何代码报错。

  ### 2.1 寻敌模块 (`ITargetingModule`)

  - **工作模式：** 情报收集器。负责在空间中扫描合法目标，决定怪物的寻敌模式(找最近的，找血量最低的)。
  - **性能规范：** 严禁在 `Update` 中每帧调用 `Vector3.Distance` 遍历全场玩家。必须使用 `searchInterval`（如 0.5 秒）进行低频轮询。
  - **通用处理逻辑：**
    1. **持有目标时：** 校验目标是否死亡（读取目标的 `Health.isDead`），或者是否超出追击极限距离（`loseTargetRange`）。若失效，则清空黑板的 `CurrentTarget`。
    2. **无目标时：** 调用 `PlayerManager` 获取最近玩家。若在 `visionRange` 内，将其写入黑板。

  ### 2.2 移动模块 (`IMovementModule`)

  - **工作模式：** 驾驶员。独占 `NavMeshAgent` 的控制权，负责靠近黑板上的目标，决定靠近目标对象的方式(走直线，尝试包围，尝试远离等)。
  - **关键状态锁 (`IsAttacking`)：** 移动模块在执行前，**必须第一步检查** `bb.IsAttacking`。一旦发现攻击模块锁死了状态，就不能进行移动（`agent.isStopped = true`），防止怪物一边滑步一边播放攻击动画。
  - **通用处理逻辑：**
    1. 计算与目标的距离并写入黑板（`DistanceToTarget`），供其他模块查阅。
    2. 到达 `stopDistance`（攻击距离）时：刹车，并通过代码插值（`Quaternion.Slerp`）锁定面向目标。最重要的一步：向黑板写入 **`IsTargetInAttackRange = true`**，通知攻击模块可以动手了。
    3. 未到达距离时：同样遵循降频更新（`pathUpdateInterval`），避免每帧 `SetDestination` 导致 CPU 寻路过载。

  ### 2.3 攻击模块与伤害检测 (`IAttackModule`)

  - **工作模式：** 杀手。一旦接到司机的通知（`IsTargetInAttackRange`），立即接管怪物的控制权，执行攻击序列。

  - **执行管线 (Coroutine)：** 必须严格遵循 `准备 (Prepare) -> 攻击/伤害判定 (Lunge) -> 收招 (Recover)` 的时间轴。

  - **主动帧伤害检测 (Active Frame Scanning)**

    - **痛点规避：** 绝对禁止使用 `OnTriggerEnter` 进行动作游戏的伤害判定，以彻底消灭“穿模漏判”和“一秒十刀”的 Bug。
    - **可视配置：** 在怪物武器/前方放置一个 `BoxCollider`，**关闭其 `enabled`**。它仅作为 Scene 窗口中的可视化绿色框线，供可视化调整判定范围。
    - **判定逻辑：** 在攻击的有效判定时间内（如 0.3 秒的 while 循环），每一帧提取该 Box 的 `Center` 和 `Size`，调用 **`Physics.OverlapBoxNonAlloc`** 进行空间扫描。
    - **去重机制：** 维护一个 `HashSet<GameObject>`（名册）。如果扫到的玩家不在名册中，则造成伤害并登记；已在名册中的直接忽略。保证一次攻击动作只造成一次伤害。

  - **伤害下发规约 (`TakeDamage`)：** 伤害接口必须传递位置与方向信息，以激活表现层。

    ```c#
    // 目标血量组件.TakeDamage(伤害值, 受击点精确坐标, 攻击打来的方向矢量);
    targetHealth.TakeDamage(damage, approximateHitPoint, transform.forward);
    ```

  ## 3. 怪物创建指南：拼装一只合格的怪物

  利用本架构，创建一个全新的多端同步怪物只需以下步骤：

  ### Step 1: 层级与组件搭建 (Hierarchy Setup)

  严格遵守父子层级分离原则。参考结构：

  - 📦 `Zombie_Standard` (根节点)
    - 📦 `Visuals` (美术模型本身)
    - 📦 `DamageHitbox` (空物体，用于调整伤害判定范围)

  ### Step 2: 根节点基础脚本挂载

  在 `Zombie_Standard` 根节点，必须挂载以下基础基建脚本：

  1. **网络基建：** `NetworkObject`, `NetworkTransform`
  2. **物理基建：** `Rigidbody` (务必冻结 X/Z 轴旋转), `CapsuleCollider`, `NavMeshAgent`
  3. **架构核心：** `MonsterEntity`, `AIBlackboard`, `MonsterBrain`, `Health`
  4. **表现路由：** `MonsterVFXController`

  ### Step 3: 行为与逻辑装配 (热插拔)

  基本上，你可以直接复制 `Zombie_Standard`，只需要你写出新的Targeter/Mover/Attacker逻辑，将他们与旧的模块混合，进行拼装，就能实现一个新的怪物逻辑。

  - 挂载 `Targeter`。
  - 挂载 `Mover`。
  - 挂载 `Attacker，并把子物体 `DamageHitbox` 拖入Hitbox` 变量槽位中。

  ### Step 4: 表现层关联 (没有美术资源是可以自己随便拿模型拼一个，用Zombie_Standard的状态机)

  1. 在 `Visuals` 层级挂载 `Animator`，配置好状态机（Move, Prepare, Attack, Die）。
  2. **极度重要：** 在根节点挂载 `NetworkAnimator`，并将子物体的 `Animator` 拖入，实现动画的跨网同步。
  3. 配置 `MonsterVFXController`，将红眼、拖尾等特效拖入其 `prebakedEffects` 列表中。

  ### Step 5: 数据注册与入库 

  1. 在 Project 窗口右键 `Create -> Data -> Monster Data`。
  2. 填写基础面板：血量 100，速度 3.5，攻击力 15，对象池 ID `"Zombie_Standard"`。
  3. **最后一步：** 把这个 SO 文件丢进全局单例 `GameDirector` 的商品目录中。发牌员会在游戏启动时**自动**将其注册进 `SyncObjectPool`。

  ------

  ## 4. 进阶规范与避坑指南 (Advanced Standards)

  为了保证联机稳定性与极致性能，开发时必须遵守以下红线：

  1. **联机权威性：** 所有的 AI 思考 (`MonsterBrain.Update`)、伤害判定 (`Attacker`)、血量扣除 (`Health.TakeDamage`) **必须被包裹在 `if (!IsServer) return;` 中**。客户端的怪物本质上只是一个没有逻辑的傀儡，只负责接收坐标同步、播放动画和生成本地特效，如果是你在只需要写Mover，Attacker，Targeter脚本的情况下，不需要担心这部分，因为MonsterBrain已经保证了三模块的脚本只在服务器上跑。
  2. **内存 GC 红线：** 在 `Update` 或判定的 `While` 循环中，绝对禁止使用 `new` 关键字（例如 `new List<Collider>()`）或调用会产生内存分配的 API（如常规的 `Physics.OverlapSphere`）。必须使用预先分配好内存的数组配合 `NonAlloc` 系列物理 API。
