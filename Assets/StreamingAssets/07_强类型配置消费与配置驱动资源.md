# 强类型配置消费：用 ID 驱动资源、挂点与动画

## 1. 方法/架构介绍

Config 加载完成后，业务层不应到处保存 Addressables 字符串。当前 Lobby 使用一条清晰的数据链：

```text
玩家状态只保存 int ID
  → ConfigManager 根据 ID 查询强类型配置
  → UI 读取 Name / Description / IconName
  → 3D 展示读取 ModleName / SpawnSlot / EquipAnim
  → Addressables 根据地址加载资源
```

这样网络只同步小而稳定的整数，资源路径、显示文案、挂点和动画都由本地同版本 Config 决定。

配置驱动的关键约束：

1. ID 是跨 UI、网络、配置和模型系统的公共契约。
2. 客户端和服务器必须使用兼容的配置版本。
3. 资源地址只在加载边界解析，不进入网络状态。
4. 来自客户端的 ID 必须由服务器再次验证。

## 2. 源码展示

### 2.1 从强类型表构建 UI 数据

节选自 `ItemSelectPresenter.InitCatalog`：

```csharp
var weaponTable =
    ConfigManager.Instance.GetTable<Config_Lobby_Weapons>();

var weaponList = new List<ItemSlotData>();
foreach (var pair in weaponTable)
{
    Config_Lobby_Weapons config = pair.Value;
    weaponList.Add(new ItemSlotData
    {
        Id = config.WeaponID,
        Name = config.Name,
        Description = config.Description,
        Category = ItemCategory.Weapon,
        ResourcePath = config.ModleName,
        IconPath = config.IconName,
    });
}
```

### 2.3 模型加载边界把 ID 解析成配置

节选自 `AvatarResManager.UpdateWeaponAsync`：

```csharp
Config_Lobby_Weapons config = GetWeaponConfig(weaponId);

EquipmentSlot equipmentSlot = ParseEquipmentSlot(
    config.WeaponSpawnSlot,

    station.SocketProvider.GetEquipmentSocket(equipmentSlot);

    Addressables.InstantiateAsync(config.ModleName, parent);
```

### 2.4 角色挂点索引与枚举映射

节选自 `CharacterSocketProvider`：

```csharp
public Transform GetEquipmentSocket(EquipmentSlot slot)
{
    if (slot == EquipmentSlot.None)
        throw new ArgumentOutOfRangeException(nameof(slot));

    int index = (int)slot - 1;
    if ((uint)index >= (uint)EquipmentSlots.Length)
        throw new ArgumentOutOfRangeException(nameof(slot));

    return EquipmentSlots[index];
}
```

`EquipmentSlot.None` 占据枚举 0，但挂点数组没有空位置，所以数组索引是 `EquipmentSlot - 1`。

### 2.5 配置值直接驱动 Animator 参数

```csharp
private static readonly int EquipmentPoseHash =
    Animator.StringToHash("EquipmentPose");

public void SetEquipmentPose(int equipmentPose)
{
    _animator.SetInteger(EquipmentPoseHash, equipmentPose);
}
```

当前约定：

```text
WeaponEquipAnim = 0 → Rifle
WeaponEquipAnim = 1 → Pistol
```

## 3. 源码解释

### 为什么网络同步 ID 而不是资源地址

假设地址平均 30 个 UTF-8 字节，而 ID 只需一个整数。同步 ID 能减少包体和字符串分配，也避免服务器必须了解 Unity Addressables 资源结构。

客户端拿到 `WeaponId=2` 后，用本地 Config 决定它显示什么模型。资源迁移到新 Group 或远端 Bundle 时，只要 Config 地址同步更新，网络协议无需变化。

### 为什么 UI 需要单独的 `ItemSlotData`

皮肤、武器、道具生成类字段并不完全一致，但选择界面只关心一组公共字段。把它们转换成统一显示数据后，格子代码无需依赖三张 Config 表。

这里讨论的是数据整形，不涉及任何 UI 组织模式。

### 为什么 SpawnSlot 和 EquipAnim 放在配置中

不同武器可以复用同一个加载流程：

```text
步枪 → RightHand + Rifle Pose
手枪 → RightHand + Pistol Pose
背包 → Back，不触发武器 Pose
```

添加内容时修改数据，不需要为每把武器新增 `if/else`。

### 为什么默认 ID 来自配置表

离线玩家和服务器新玩家使用：

```csharp
ConfigManager.Instance
    .GetTable<Config_Lobby_Weapons>()
    .Keys.Min();
```

这保证默认值一定存在于当前表中，而不是在代码里硬编码一个可能已被策划删除的 ID。

## 4. 底层拓展说明

### 4.1 服务器必须验证 ID

客户端可以伪造 RPC 参数。`LobbyNetworkManager` 在写入 `NetworkList` 前执行：

```csharp
if (!ConfigManager.Instance
    .GetTable<Config_Lobby_Weapons>()
    .ContainsKey(id))
{
    throw new ArgumentOutOfRangeException(nameof(id));
}
```

客户端 UI 中存在这个 ID，不代表服务器可以信任请求。

### 4.2 配置版本必须与资源 Catalog 匹配

Config 中已经出现新地址，但客户端 Catalog 仍是旧版，会产生找不到 Address 的错误。远端更新时应保证：

```text
Catalog、Config bytes、依赖 AssetBundle
```

属于同一个可回滚版本。

### 4.3 不要随意修正生成字段拼写

当前字段叫 `ModleName`。它拼写不理想，但由 Excel 表头生成，且业务代码已经依赖。只改生成的 C# 文件会在下次生成时被覆盖。

正确重命名需要同时更新 Excel 字段名、所有消费代码、重新生成类、重新导出 bytes、重新生成 Formatter，并评估旧二进制兼容。

### 4.4 空表不是合法默认状态

`Keys.Min()` 在空表上会抛异常。这是合理的失败方式：Lobby 的皮肤、武器和道具属于启动必需数据。构建管线应更早校验每张必需表至少有一行数据。

### 4.5 ID 是否可以复用

已经进入存档或网络协议的 ID 不建议复用成另一种物品。删除内容时可以保留弃用记录，或通过版本迁移把旧 ID 映射到新 ID。

## 5. 应用示例

### 示例：添加一把新手枪

Config 行需要完整描述：

```text
WeaponID       = 12
Name           = 轻型手枪
ModleName      = Lobby/Weapons/Pistol_Light
IconName       = Lobby/Icons/Pistol_Light
Description    = 轻便的半自动手枪
WeaponSpawnSlot= RightHand 对应整数
WeaponEquipAnim= 1
```

上线前检查：

1. `WeaponID=12` 唯一且不会复用旧内容。
2. 模型和 Sprite 地址已经进入 Addressables Catalog。
3. 模型预制件挂有 `WeaponVisualPoints`，若当前展示链需要其标记。
4. 角色预制件 `EquipmentSlots[(int)RightHand - 1]` 已绑定。
5. Animator 含整数参数 `EquipmentPose`，值 1 能进入 Pistol 状态。
6. 重新导出 Config bytes 和 Addressables 内容。
7. Host 与 Client 使用同一版本 Config。

业务代码无需新增这把武器的专用分支。
