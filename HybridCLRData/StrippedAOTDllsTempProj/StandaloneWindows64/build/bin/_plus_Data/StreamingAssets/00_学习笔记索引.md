# Unity 实用基础设施学习笔记：阅读索引

## 这套笔记解决什么问题

这套笔记从当前项目的真实源码出发，说明一条资源与数据如何从编辑器进入运行时，并最终驱动 LobbyScene：

```text
Excel
  → 生成强类型 Config 类
  → MessagePack 序列化为 .bytes
  → 注册为 Addressables Config 标签
  → ConfigManager 异步加载并反序列化
  → Lobby 通过强类型 ID 查询配置
  → Addressables 加载角色、武器、道具和图标
  → NGO 同步玩家选择
  → 同一份玩家快照刷新展位 UI 与 3D 模型
```

内容刻意不讲 MVP 和策略模式。即使源码文件名或接口具有这些结构，本笔记也只讨论资源管理、异步、序列化、数据管线、网络同步和本地存储等可直接复用的工程能力。

> 注意：当前目录叫 `Assets/StreamingAsset`，没有结尾的 `s`。它在本项目中只是学习资料目录，不等同于 Unity 特殊目录 `Assets/StreamingAssets`，也不会自动通过 `Application.streamingAssetsPath` 暴露。

## 先记住的五条原则

1. Addressables 句柄代表资源所有权；加载成功不等于可以忘记 `Release`。
2. `await` 只保证当前方法按顺序继续，不保证“结果仍然属于当前界面状态”；竞态仍需版本号或取消令牌处理。
3. MessagePack 的数字 `Key` 是二进制 Schema，不是随便调整的字段序号。
4. 客户端提交的是请求，服务器保存的才是联机权威状态。
5. 配置表、用户设置和网络包服务于不同目标，不要因为它们都能“序列化”就强行使用同一种格式。

## 三种数据形式的选择

| 数据 | 当前项目方式 | 主要原因 |
| --- | --- | --- |
| 大批量只读配置 | MessagePack `.bytes` + Addressables | 体积小、读取快、可以随资源版本更新 |
| 玩家本地可编辑设置 | JSON + `persistentDataPath` | 可读、易排错、数据量小 |
| 联机大厅实时状态 | NGO `INetworkSerializable` + `NetworkList` | 增量同步、服务器权威、自动通知客户端 |

这三条链路可以共享同一套 Config ID，但不应互相替代。
