# 地图生成架构与脚本挂载说明

更新日期：2026-08-09

本文档对应 `Assets/_HotUpdate/Scripts/GameProcess/Map` 下的当前实现，说明：

- 地图生成、模板选择、网络同步和对象池构建的数据链路。
- 场景中必须挂载的脚本及 Inspector 字段。
- 房间预制体和连接预制体必须挂载的脚本、层级和锚点规范。
- `RoomConfig`、`PoolConfig` 与 Addressables 的对应关系。
- Map 目录中每个脚本是否需要挂载，以及各自职责。

## 1. 当前架构概览

当前地图由 Server 生成唯一逻辑结果，再将同一份最终构建数据同步给 Client：

```text
ConfigManager
├─ Config_RoomTemplate
└─ Config_LocalObjectPool

Server
MapGenerationController
→ GridGraphLayoutStrategy
→ MapLayout
→ GridRoomTemplateSelector
→ MapBuildPlan
├─→ 本机 MapVisualBuilder
└─→ ClientRpc

Client
MapBuildPlan
→ MapVisualBuilder
→ LocalObjectPool
→ Room Prefab / Connection Prefab
```

关键原则：

1. 只有 Server 执行拓扑生成和房间模板选择。
2. Client 不重新随机，直接使用 Server 下发的 `MapBuildPlan`。
3. 房间始终是本地视觉对象，由每台机器自己的 `LocalObjectPool` 创建；逻辑连接始终存在，但是否创建 `ConnectionView` 由策略的 `ConnectionMode` 决定。
4. `TemplateId`、Pool 配置、Addressables 内容必须在 Server 和 Client 版本间完全一致。
5. 当前 `GridGraphLayoutStrategy` 只实际生成 `Start`、`Combat` 和 `Boss` 三种房间，并声明 `ConnectionMode = Seamless`，不会申请或实例化连接预制体。
6. Grid 每层只随机一次统一 `RoomScale`；该值进入 `MapLayout`、`MapBuildPlan` 和网络序列化，Server/Client 使用同一缩放。

## 2. 推荐场景层级与初始化顺序

推荐的 `GameRunTimeScene` 层级如下：

```text
GameRoot                                      [NetworkObject]
├─ GameRuntimeBootstrap                      [GameRuntimeBootstrap]
├─ LocalObjectPool                           [LocalObjectPool]
│  └─ InactiveRoot                           [可选；池内闲置对象父节点]
├─ RoomTemplateCatalog                       [RoomTemplateCatalog]
├─ MapVisualBuilder                          [MapVisualBuilder]
│  ├─ RoomRoot                               [运行时房间父节点]
│  └─ ConnectionRoot                         [运行时连接父节点]
└─ MapGenerator                              [仅作层级分组时可保留]
```

`MapGenerationController` 是 `NetworkBehaviour`。最稳妥的挂载方式是直接挂在拥有 `NetworkObject` 的 `GameRoot` 上；如果挂在其子物体上，必须确认 NGO 能将它归属到已经 Spawn 的 `NetworkObject`，否则 `InitializeAsync()` 会一直等待 `IsSpawned`。

`GameRuntimeBootstrap._runtimeServiceComponents` 中与地图有关的顺序必须是：

```text
LocalObjectPool
→ RoomTemplateCatalog
→ MapVisualBuilder
→ MapGenerationController
```

原因：

- `RoomTemplateCatalog` 依赖 `ConfigManager` 已经加载 `Config_RoomTemplate`。
- `MapVisualBuilder` 初始化时检查 `LocalObjectPool` 和 `RoomTemplateCatalog`。
- `MapGenerationController` 初始化时检查 `RoomTemplateCatalog` 和 `MapVisualBuilder`，并等待自身完成 Network Spawn。

地图运行时服务建议完整顺序：

```text
GameNetworkRuntime
→ LocalObjectPool
→ SyncObjectPool
→ LocalVFXPool
→ PlayerManager
→ RoomTemplateCatalog
→ MapVisualBuilder
→ MapGenerationController
```

注意：初始化完成不等于自动生成地图。上层流程仍需在 Server 进入 `MapGenerating` 状态后调用：

```csharp
await mapGenerationController.GenerateAndBuildAsync(
    level,
    playerCount,
    cancellationToken);
```

## 3. 场景组件挂载说明

### 3.1 RoomTemplateCatalog

挂载位置：`GameRoot/RoomTemplateCatalog`。

职责：

- 从 `ConfigManager.GetTable<Config_RoomTemplate>()` 读取房间模板配表。
- 按 `TemplateId` 升序建立稳定的模板列表。
- 建立 `TemplateId → RoomTemplateConfig` 查询字典。
- 校验房间类型、PoolId、连接掩码、旋转掩码和随机权重。

Inspector 字段：无。

旧版 Inspector 中的手工 `_templates` 列表已移除。模板只能通过 `RoomConfig.xlsx` 修改。

前置条件：

- `HotFixEntry` 已执行 `ConfigManager.LoadAllConfigsAsync()`。
- `Config_RoomTemplate.bytes` 已加入 Addressables，且带有 `Config` 标签。

### 3.2 MapVisualBuilder

挂载位置：`GameRoot/MapVisualBuilder`。

职责：

- 收集本层地图需要的房间 PoolId 和连接 PoolId。
- 调用 `LocalObjectPool.PreparePoolsAsync()` 加载并预热资源。
- Rent 房间预制体，注册 `RoomViewRuntime`。
- 按连接掩码切换墙体和门框。
- 根据构建方案的连接呈现模式处理逻辑连接：Grid 只校验重合插槽并登记 Portal；需要走廊的策略才 Rent、定位和拉伸 `ConnectionView`。
- 建立 Room、Connection、Portal 的运行时查询索引。
- 控制房间相关的战斗门开关。
- Clear 或 Shutdown 时恢复视觉状态、归还实例并释放持有的 Pool。

Inspector 字段：

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_roomRoot` | 否 | 运行时房间实例的父节点。为空时使用 `MapVisualBuilder.transform`。建议显式绑定，便于查看层级。 |
| `_connectionRoot` | 否 | 运行时连接实例的父节点。为空时使用 `MapVisualBuilder.transform`。建议显式绑定。 |
| `_templateCatalog` | 是 | 必须绑定场景中的 `RoomTemplateCatalog`。 |
| `_gridConnectionPoolId` | 条件必填 | 仅 `ConnectionMode = ConnectionView` 且存在连接时读取。Grid 的 `Seamless` 模式不会读取、申请或实例化该 Pool。 |
| `_minimumAnchorFacingDot` | 是 | 两端 Connector 朝向校验阈值。默认 `0.8`，约等于最多允许 36.9° 偏差。 |
| `_maximumAnchorHeightDifference` | 是 | 两端 Connector 世界坐标 Y 的最大允许差，默认 `0.2`。 |
| `_seamPositionTolerance` | 是 | Seamless 模式下两个 Connector 世界坐标允许的最大误差，默认 `0.02`，会随整层 RoomScale 同比缩放。 |

### 3.3 MapGenerationController

挂载位置：推荐与 `GameRoot.NetworkObject` 同一物体。

职责：

- Server 创建随机 Seed，并生成逻辑地图。
- Server 选择房间模板和旋转角度。
- Server 先构建本机地图，再通过 ClientRpc 下发同一份 `MapBuildPlan`。
- Client 收到方案后直接构建，不重新生成和选择。
- Client 构建完成后通过 ServerRpc 报告 Ready。
- Server 等待所有连接中的 Client Ready。
- 处理地图清理、旧构建取消、迟到包过滤和重连地图重发。

Inspector 字段：

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_templateCatalog` | 是 | 场景中的 `RoomTemplateCatalog`。 |
| `_visualBuilder` | 是 | 场景中的 `MapVisualBuilder`。 |
| `_gridProfile` | 是 | 内嵌的 GridGraph 生成参数，不是独立组件。 |
| `_clientReadyTimeoutSeconds` | 是 | Server 等待全部 Client 完成地图视觉构建的最长时间，默认 20 秒。应覆盖较慢设备的 Addressables 加载时间。 |

`_gridProfile` 子字段：

| 字段 | 默认值 | 作用与限制 |
|---|---:|---|
| `_minRoomCount` | 12 | 最少房间数，必须至少为 2。 |
| `_maxRoomCount` | 16 | 最多房间数，不能小于最少房间数。 |
| `_minBossDistance` | 6 | Boss 距离起点的最少拓扑步数；必须大于 0 且小于 `_minRoomCount`。 |
| `_maxConnectionsPerRoom` | 4 | 单房间最大连接数，只允许 2～4。 |
| `_baseRoomSize` | 70 | Scale=1 时正方形房间的基础边长；由旧字段 `_roomSpacing` 自动迁移。 |
| `_allowedRoomScales` | 0.75/1/1.25 | 生成前按 Seed 随机一次，整层所有房间共享同一 Scale；必须全部为大于 0 的有限数值。 |
| `_maxGenerationAttempts` | 20 | 同一请求最多重试次数；每次尝试使用可复现的派生 Seed。 |

网络要求：

- 组件必须属于已 Spawn 的 `NetworkObject`。
- Server 和 Client 必须具有相同的 NetworkBehaviour 结构和脚本版本。
- 只有 Server 可以调用 `GenerateAndBuildAsync()`、`ClearCurrentMapAsync()` 和 `SendCurrentMapToClientServer()`。

### 3.4 Map 目录外的必需依赖

#### LocalObjectPool

挂载位置：`GameRoot/LocalObjectPool`。

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_inactiveRoot` | 否 | 池内闲置实例的父节点；为空时使用池组件自身 Transform。 |

房间和连接的 Pool 定义来自 `Config_LocalObjectPool`。`MapVisualBuilder` 不会直接 `Instantiate` 配表中的 Prefab。

#### GameRuntimeBootstrap

挂载位置：`GameRoot/GameRuntimeBootstrap`，并属于已 Spawn 的 NetworkObject。

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_runtimeServiceComponents` | 是 | 按数组顺序初始化服务、按相反顺序关闭服务。必须把 `MapGenerationController` 放在 `MapVisualBuilder` 后面。 |
| `_requiredSceneNames` | 按项目需要 | 本地运行时 Ready 前必须等待的 Additive 场景，如 `UIGameUIScene`。 |

## 4. 房间预制体挂载规范

### 4.1 推荐层级

```text
RoomPrefabRoot                              [RoomView]
├─ VisualRoot                              [房间模型]
├─ SpawnPoints
│  ├─ Enemy_00
│  ├─ Player_00
│  ├─ Chest_00
│  └─ NextLevel_00
├─ Connector_North                        [RoomConnectorSlot]
│  ├─ ClosedWallRoot
│  ├─ OpenFrameRoot
│  └─ BattleGateRoot                      [可选；Grid 战斗封门]
├─ Connector_East                         [RoomConnectorSlot]
│  ├─ ClosedWallRoot
│  └─ OpenFrameRoot
├─ Connector_South                        [RoomConnectorSlot]
│  ├─ ClosedWallRoot
│  └─ OpenFrameRoot
└─ Connector_West                         [RoomConnectorSlot]
   ├─ ClosedWallRoot
   └─ OpenFrameRoot
```

### 4.2 RoomView

挂载位置：房间预制体根节点，且每个房间只能有一个。

必须挂在根节点的原因：

```csharp
roomObject.TryGetComponent(out RoomView roomView)
```

构建器不会到子节点搜索 `RoomView`。挂在子节点会直接抛出“房间预制体缺少 RoomView”。

职责：保存房间中可供其他玩法系统读取的静态出生点。

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_enemySpawnPoints` | 按房间玩法 | 敌人出生候选点。Map 构建器只保存并暴露，不负责生成敌人。 |
| `_playerSpawnPoints` | 起点/复活房建议填写 | 玩家进入地图或房间时的出生候选点。 |
| `_chestSpawnPoints` | 宝藏或奖励房建议填写 | 宝箱、奖励物的候选点。 |
| `_nextLevelPoints` | Boss/终点房建议填写 | 下一层传送门或出口的候选点。 |

数组可以为空，但调用方必须能处理空列表。为了避免业务脚本遇到 null，建议在 Inspector 中保持空数组而不是未初始化状态。

### 4.3 RoomConnectorSlot

挂载位置：房间预制体内部每一个可能连接方向的锚点节点。

组件所在 Transform 就是连接锚点，不需要再绑定 Anchor 字段。

职责：

- 表明当前房间在某个局部方向上是否具有连接能力。
- 提供关闭墙体与打开门框两套模型根节点。
- 提供入口数学平面的宽度和高度。
- 为连接预制体提供定位、朝向和 Portal 尺寸数据。

Inspector 字段：

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_slotId` | 是 | 同一房间内唯一的可读 ID，如 `North`、`Entrance_A`。当前 GridGraph 不用它查方向，但应保持唯一，便于诊断和后续自由连接策略。 |
| `_direction` | 是 | GridGraph 使用 `North/East/South/West`；只有未来自由走廊插槽使用 `None`。同一房间不能出现两个相同的非 None 方向。 |
| `_closedWallRoot` | 强烈建议 | 此方向没有连接时显示的完整墙体。 |
| `_openFrameRoot` | 强烈建议 | 此方向存在连接时显示的开口墙或门框。 |
| `_battleGateRoot` | 玩法可选 | Grid 不生成 ConnectionView，因此需要封门时在房间插槽上绑定门模型与碰撞体；为空时只保留逻辑锁定。 |
| `_portalWidth` | 是 | 目标房间入口数学平面的宽度，默认 4。 |
| `_portalHeight` | 是 | 目标房间入口数学平面的高度，默认 3。 |

锚点 Transform 规范：

- Local Position：位于墙体开口中心。
- Local Rotation：`forward` 必须朝房间外部、指向相邻房间。
- Local X：Portal 宽度方向。
- Local Y：Portal 高度方向。
- 相对的两个房间锚点高度差不能超过 `MapVisualBuilder._maximumAnchorHeightDifference`。
- Grid Seamless 模式要求相邻两个锚点的世界坐标在 `_seamPositionTolerance × RoomScale` 内重合，且两者 forward 点积不大于 `-_minimumAnchorFacingDot`。
- Scene 视图选中 Connector 后，青色框表示入口平面，黄色线表示 `forward`。

房间四向约定：

| Direction | 房间局部方向 | 推荐 Local Position | forward |
|---|---|---|---|
| North | +Z | 北墙开口中心 | +Z |
| East | +X | 东墙开口中心 | +X |
| South | -Z | 南墙开口中心 | -Z |
| West | -X | 西墙开口中心 | -X |

### 4.4 Grid 正方形房间与无缝拼接约束

Grid 使用如下固定关系，不再为房间之间预留通道长度：

```text
RoomSpacing = BaseRoomSize × RoomScale
RoomRoot.localScale = (RoomScale, RoomScale, RoomScale)
WorldPosition = GridCoordinate × RoomSpacing
```

Grid 房间资源必须满足：

- 房间平面是正方形，Scale=1 时边长等于 `_baseRoomSize`。
- Prefab 根 Pivot 位于正方形底面的严格中心，因此所有房间根节点的 Y 可统一为 0。
- 四个方向 Connector 位于边界开口中心，未缩放时分别距 Pivot `_baseRoomSize / 2`。
- 房间允许旋转，但只允许 0/90/180/270°，不允许非均匀缩放。
- 房间仍必须配置全部真实可用的 `RoomConnectorSlot`；它可能被其他生成策略复用，同时 Grid 也需要插槽来切墙、登记 Portal 和控制战斗门。

以上资源约束与运行时重合校验共同保证相邻 Grid 房间严丝合缝。模型尺寸或 Connector 位置错误时，构建会直接失败并报告两个锚点的距离，不会静默生成裂缝或重叠。

### 4.5 房间 Prefab 与配表必须一致

如果 `RoomConfig` 的 `SupportedConnectorMask` 为 15，预制体必须真实存在四个不同方向的 `RoomConnectorSlot`。

如果配表声明支持某方向但预制体缺少该方向：

```text
模板选择阶段会认为模板可用
→ MapVisualBuilder 实例化房间
→ ResolveRequiredConnector 找不到插槽
→ 构建失败并回收地图实例
```

反过来，如果预制体存在额外插槽但配表没有声明，该模板不会充分利用真实结构，因此也属于配置错误。

### 4.6 房间预制体的对象池要求

每个 `RoomTemplate.PoolId` 必须在 `PoolConfig.xlsx / LocalObjectPool` 中有对应行：

| PoolConfig 字段 | 要求 |
|---|---|
| `ConfigId` | 唯一整数主键。 |
| `PoolId` | 与 `RoomTemplate.PoolId` 完全一致，区分大小写。 |
| `GroupName` | 建议填写 `MapRoom` 或具体房间分组。 |
| `PrefabAddress` | 房间 Prefab 的 Addressables 地址。 |
| `InitialCapacity` | 不小于 0，且不能大于 `MaxSize`。 |
| `MaxSize` | 必须大于 0，并覆盖单层地图可能同时存在的实例数量。 |

房间 Prefab 本身必须加入 Addressables。当前地图是本地视觉对象，通常不应在房间根节点再挂 `NetworkObject`；需要联网的敌人或交互物应由各自网络生成链路负责。

如果房间上还有会残留状态的自定义组件，建议实现对象池的 `IPoolable` 回调，在 Rent/Return 时重置。Map 系统只负责恢复 Connector 的墙体/门框状态。

当前已登记的 Grid 房间资源为：

| 用途 | RoomType | PoolId / Addressable 地址 | Prefab |
|---|---:|---|---|
| 起始房 | 1（Start） | `Room_Grid_Start` | `Assets/_HotUpdate/Prefabs/Rooms/Room_Grid_Start.prefab` |
| 怪物房 | 2（Combat） | `Room_Grid_Monster` | `Assets/_HotUpdate/Prefabs/Rooms/Room_Grid_Monster.prefab` |
| Boss 房 | 6（Boss） | `Room_Grid_Boss` | `Assets/_HotUpdate/Prefabs/Rooms/Room_Grid_Boss.prefab` |

三条 `RoomTemplate` 的 `AllowedStrategyMask` 均为 `1`，因此只会进入 GridGraph 候选列表。三个 Prefab 均由同一个场景 `Room` 原样保存，只区分资源名和根节点名。

## 5. 连接预制体挂载规范（仅 ConnectionView 模式）

Grid 的 `ConnectionMode` 为 `Seamless`，不会创建本节所述预制体。房间仍要挂 `RoomConnectorSlot`，以便同一房间模板可被未来 Corridor 等需要 `ConnectionView` 的策略复用。

### 5.1 推荐层级

```text
ConnectionPrefabRoot                        [ConnectionView]
└─ StretchRoot                              [沿本地 Z 轴拉伸]
   ├─ CorridorVisual
   ├─ BattleGateRoot                        [门模型及碰撞体]
   ├─ PortalA                               [靠近本地 -Z 端]
   └─ PortalB                               [靠近本地 +Z 端]
```

`PortalA`、`PortalB` 推荐放在会沿 Z 缩放的层级中，使它们在 `StretchRoot` 拉伸后仍位于通道两端。

### 5.2 ConnectionView

挂载位置：连接预制体根节点，且只能有一个。

必须挂在根节点的原因：

```csharp
connectionObject.TryGetComponent(out ConnectionView connectionView)
```

Inspector 字段：

| 字段 | 必填 | 作用 |
|---|---:|---|
| `_stretchRoot` | 是 | 被构建器沿本地 Z 轴拉伸的模型根节点。缺失会立即抛出异常。 |
| `_baseLength` | 是 | `StretchRoot.localScale == 原始值` 时的模型实际长度，沿本地 Z 轴计算，必须大于 0。 |
| `_battleGateRoot` | 玩法可选 | 战斗期间用于封锁连接的模型/碰撞体根节点。为空时 `SetRoomConnectionsLocked()` 不产生视觉或碰撞效果。 |
| `_portalA` | 是 | 靠近 Room A 的数学入口平面。构建后应靠近 A 端，`forward` 朝 Room A 内部。 |
| `_portalB` | 是 | 靠近 Room B 的数学入口平面。构建后应靠近 B 端，`forward` 朝 Room B 内部。 |

运行时坐标约定：

- 构建器让连接根节点的本地 +Z 指向 `Room A → Room B`。
- PortalA 位于本地 -Z 端，`forward` 朝 -Z，也就是 Room A 内部。
- PortalB 位于本地 +Z 端，`forward` 朝 +Z，也就是 Room B 内部。
- `StretchRoot` 只改变本地 Z 缩放，不改变 X/Y。
- 地图刚生成时 `_battleGateRoot` 默认关闭；战斗开始后由 `SetRoomConnectionsLocked(roomId, true)` 打开。

Portal 只是数学 Transform，不要求自身带 Trigger Collider。实际玩家跨房判定系统通过 `RoomPortalRuntime` 读取平面 Transform、半宽和半高。

### 5.3 连接预制体对象池要求

只有生成策略声明 `ConnectionMode = ConnectionView` 时，连接 Pool 才必须在 `PoolConfig.xlsx / LocalObjectPool` 中登记：

```text
PoolId          = Connection_Grid
GroupName       = MapConnection
PrefabAddress   = 连接预制体的 Addressables 地址
InitialCapacity = 建议接近最少连接数量
MaxSize         = 至少覆盖 MaxRoomCount - 1
```

当前 GridGraph 是无环树，逻辑连接数量固定为：

```text
Connections = Rooms - 1
```

但 Grid 不会为这些逻辑连接创建视觉对象。需要 ConnectionView 的其他策略仍应通过对象池创建，不应在场景中放置一个孤立 `ConnectionView` 充当模板。

## 6. RoomConfig 配表字段说明

文件：`Assets/DesignData/Excels/RoomConfig.xlsx`，工作表：`RoomTemplate`。

| 字段 | 作用 | 要求 |
|---|---|---|
| `TemplateId` | 稳定模板 ID，会进入 `MapBuildPlan` 并通过网络同步。 | 大于 0、不可重复；发布后不要随意复用旧 ID。 |
| `RoomType` | 模板可用于哪种玩法房间。 | 必须是有效 `RoomType`。 |
| `AllowedStrategyMask` | 模板允许参与的生成策略位掩码。 | `1=GridGraph`、`2=Corridor`、`3=两者`；异形房间不要包含 GridGraph 位。 |
| `PoolId` | 对应 `Config_LocalObjectPool.PoolId`。 | 非空、大小写完全一致。 |
| `SupportedConnectorMask` | 预制体旋转前真实拥有的局部方向插槽。 | 1～15 的有效方向组合。 |
| `AllowUnusedConnectors` | 是否允许预制体存在本次地图未使用的额外插槽。 | true 时额外插槽保持封墙；false 时模板插槽必须与需求完全相等。 |
| `AllowedRotations` | 模板允许使用的 0/90/180/270° 旋转。 | 1～15 的有效旋转组合。 |
| `Priority` | 模板选择优先级。 | 只在最高优先级的兼容模板中进行权重随机。 |
| `Weight` | 同优先级兼容模板的随机权重。 | 必须是大于 0 的有限数值。 |

### 6.1 RoomType

| 数值 | 枚举 | 当前 GridGraph 是否生成 |
|---:|---|---:|
| 0 | None | 否，非法配置 |
| 1 | Start | 是 |
| 2 | Combat | 是 |
| 3 | Elite | 否 |
| 4 | Treasure | 否 |
| 5 | Shop | 否 |
| 6 | Boss | 是 |

### 6.2 SupportedConnectorMask

注意：这里是位掩码，不是 `ConnectorDirection` 的枚举序号。

| 数值 | 方向 |
|---:|---|
| 1 | North |
| 2 | East |
| 4 | South |
| 8 | West |
| 15 | North + East + South + West |

组合值通过相加得到，例如：

```text
North + South = 1 + 4 = 5
East + West   = 2 + 8 = 10
North + East + South = 1 + 2 + 4 = 7
```

### 6.3 AllowedRotations

| 数值 | 旋转 |
|---:|---|
| 1 | 0° |
| 2 | 90° |
| 4 | 180° |
| 8 | 270° |
| 15 | 全部旋转 |

模板选择流程为：

```text
AllowedStrategyMask 包含当前 StrategyType
→ RoomType 匹配
→ 枚举 AllowedRotations
→ 旋转 SupportedConnectorMask
→ 检查能否覆盖当前房间连接需求
→ 保留最高 Priority
→ 按 Weight 随机模板
→ 在该模板的合法旋转中随机一个 RotationIndex
```

每个房间使用 `Map Seed + RoomId + RoomType` 派生独立随机种子。因此同一份配表、同一 Seed 和同一 RoomId 会得到稳定结果。

## 8. 运行时调用与清理要求

生成当前层：

```text
Server GenerateAndBuildAsync
→ 创建 Seed
→ 使用独立随机流选择本层统一 RoomScale
→ 生成 MapLayout
→ 按策略过滤并选择模板，生成含 ConnectionMode/RoomScale 的 MapBuildPlan
→ Server 本地 Build
→ ClientRpc(MapBuildPlan)
→ Client 本地 Build
→ Client Ready ServerRpc
→ Server 等待全部 Ready
```

切层或返回大厅前：

```text
Server ClearCurrentMapAsync
→ ClientRpc 清理
→ MapVisualBuilder.ClearMapVisualsAsync
→ ConnectionView 恢复原始缩放；ConnectionView 或房间插槽战斗门关闭
→ 房间 Connector 恢复封墙
→ 所有实例 Return
→ 释放地图持有的 Pool
```

不要直接 `Destroy` 正在由 MapVisualBuilder 持有的房间或连接对象，也不要绕过 Builder 手动 Rent 同一批地图对象，否则运行时字典和对象池租借计数会失去一致性。
