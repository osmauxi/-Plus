# 场景地编与关卡搭建规范

本文档为本项目场景与关卡搭建的唯一执行标准。为保障程序自动生成逻辑的精确性以及双人联机状态下物理与网络同步的稳定性，请地编组务必严格遵守以下尺寸、命名与层级规范。

## 一、 基础搭建准则与物理铁律

### 1. 坐标与底板基准

- **绝对原点：** 所有房间预制件（Prefab）的中心坐标（Pivot）必须严格位于地板平面的正中心 `(0, 0, 0)`。
- **开发底板：** 任何新房间的搭建，**必须基于工程内提供的 `SampleRoom` 预制件进行修改**。该底板的尺寸为 `Scale(7, 7, 7)` 的 Plane，SampleRoom位于Assets/Prefab/Rooms，注意，**不能直接打开SampleRoom进行修改，应该把SampleRoom拉进你自己的Scene中，此时场景中的SampleRoom是蓝色的，右键它，选择Prefab/UnpackCompletely，此时场景中SampleRoom的方块变为无色，即可开始在你的场景中进行地编工作，完成之后，在你的文件夹中保存为新的预制件。**
- **通道预留：** `SampleRoom` 的四个方向正中心已放置了尺寸为 `Scale(7, 7, 0.9)` 的占位方块，代表房间出入口。请勿在此区域放置任何阻挡物。**房间搭建完成后，导出预制件前，必须删除这四个占位门以及表示玩家大小的胶囊体。**

### 2. 物理与地形铁律 (极其重要)

- **绝对纯平射击域：** 鉴于本项目的核心射击管线基于二维平面判定，**玩家与怪物的可行走区域（地板面）必须保持绝对的纯平（Y轴高度一致）**。禁止搭建任何改变角色 Y 轴坐标的斜坡或阶梯。地形的起伏感仅限通过不可进入的背景装饰、墙体高度差或法线贴图来表现。
- **碰撞层物理隔离：** * **场景模型（包括墙壁、掩体、装饰物）绝对禁止挂载任何 `Collider` 或 `Rigidbody` 组件。**
  - 所有的场景碰撞体，必须使用独立的“空物体（Empty GameObject）”并挂载放大的 `BoxCollider` 来代替，以降低物理引擎与网络同步的开销。

------

## 二、 预制件层级规范

为确保程序能够通过相对路径精准检索组件，房间内所有物体必须遵循严格的父子级结构。任何新创建的房间预制件，根节点下必须且只能包含以下三个主要子节点：

```
Room_类型_编号 (预制件根节点)
 │
 ├── Environment  // 视觉表现层
 │   └── (存放所有场景模型、点光源、特效粒子。模型不可带碰撞箱)
 │
 ├── Colliders    // 物理阻挡层
 │   └── (存放所有作为碰撞墙的空物体，挂载 BoxCollider，地面Layer为Ground，墙壁Tag为Wall)
 │
 └── SpawnNodes   // 生成插槽层 (下文详述)
     ├── Node_Reward
     ├── Node_Enemy_1
     └── ...
```

------

## 三、 零代码“插槽”生成系统

程序的生成逻辑采用“插槽读取”模式。地编人员无需挂载任何脚本，只需在 `SpawnNodes` 节点下放置**空物体 (Empty GameObject)** 并严格按照以下规则命名，程序即可自动完成物件与怪物的实例化。

### 1. 战利品/设施生成插槽

- **命名约定：** `Node_Reward`
- **放置要求：** 存在于商店房、宝箱房及怪物房。需放置于房间内视觉中心或显眼位置。必须确保其周围无任何碰撞体阻挡，以防止宝箱或祭坛生成后发生穿模。

### 2. 怪物生成插槽

- **命名约定：** `Node_Enemy_1` 至 `Node_Enemy_12`
- **放置要求：** 仅存在于怪物房。地编需在可行走区域内，均匀、分散地放置 8 到 12 个生成插槽。
- **位置限制：** 1. 绝对禁止放置在四个出入口附近（防止怪物生成后堵死通道）。 2. 必须远离墙壁与掩体，确保空物体周围有足够的寻路空间。

### 3. 玩家初始插槽

- **命名约定：** `Node_PlayerStart`
- **放置要求：** 仅存在于“起点房间”。放置于房间正中心。

## 四、 命名与对象池注册约定

关卡自动生成算法强依赖预制件的命名规范，命名错误将导致房间无法被正确加载或对象池报错。

### 1. 命名格式

- **格式：** `Room_[房间类型]_[序号]`
- **类型枚举：**
  - `1` = 商店房间(无怪物，需放置 `Node_Reward`)
  - `2` = 怪物房间 (需放置 8-12 个 `Node_Enemy`，1 个 `Node_Reward`)
  - `3` = 宝箱房间 (无怪物，需放置 `Node_Reward`)
  - *(注：Boss房间目前暂定为空旷场地，后续引入单独规范)*

### 2. 命名示例

- 第一种样式的商店房：`Room_1_0`
- 第一种样式的怪物房：`Room_2_0`
- 第二种样式的怪物房：`Room_2_1`

**对象池对接：** 制作完成并检查无误的预制件，请移动至 `Assets/_Cooperation/_LevelDesign/你的目录` 下，该预制件的文件名必须与上述命名约定完全一致。

## 五、 地编出包自检清单 (Checklist)

在导出或提交任何房间预制件前，请自行核对以下列表：

- [ ] 根节点 Pivot 是否为 `(0, 0, 0)`？
- [ ] 占位的四个门方块和玩家胶囊体是否已删除？
- [ ] `Environment` 里的模型是否已清空所有 `MeshCollider` 和 `BoxCollider`？
- [ ] 是否已在 `Colliders` 节点下用空物体构建了包围盒？
- [ ] `SpawnNodes` 下的生成点命名拼写是否正确？
- [ ] 预制件命名是否符合 `Room_X_Y` 规范？
