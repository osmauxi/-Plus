网络发送量在三个档位都稳定下降到原来的约 54%～60%。帧时保持在原量级，2048 Client 的平均帧时和 P95 还略有下降，1024 Host 的尾部变化相对明显，需要用更多重复确认。当前链路已经取得网络侧收益，尚未表现出稳定的渲染帧时下降。

## 2. 当前 10024 压测和旧网络大包参照

当前 10024 三次前台轮的平均值如下：

| 角色 | 平均帧时 | P95 帧时 | 平均 Main Thread | P95 Main Thread | 应用层网络 |
|---|---:|---:|---:|---:|---:|
| Host | 18.77 ms | 31.55 ms | 18.74 ms | 31.54 ms | 发送约 656.9 KiB/s，合计约 659.5 KiB/s |
| Client | 11.18 ms | 12.94 ms | 11.17 ms | 12.92 ms | 接收约 684.0 KiB/s，合计约 686.3 KiB/s |

旧 10024 参照为 Host 发送 903.49 KiB/s、Client 接收 904.27 KiB/s，Host 平均帧时 21.981 ms、P95 36.288 ms，Client 平均帧时 12.557 ms、P95 16.079 ms。当前结果的方向性变化如下：

| 角色 | 平均帧时 | P95 帧时 | 网络载荷 | GC 平均分配 |
|---|---:|---:|---:|---:|
| Host | -14.6% | -13.0% | -27.0% | +208.9% |
| Client | -11.0% | -19.5% | -24.1% | +206.9% |

网络侧从约 904 KiB/s 降到约 660～686 KiB/s，说明完整房间快照拆成群组并按层分频已经在 10024 规模生效。发送消息数量从旧链路约 59 条/s 增加到当前 Host 约 1,900 条/s，接收端约 1,800～1,940 条/s，平均消息大小从约 15.6 KiB 降到约 350～400 B。当前传输已经从“少量大消息”转为“较多小消息”，带宽下降来自每包内容和发送频率，消息调度次数明显上升。

当前 10024 的群组 Marker 与网络结果一起看，说明分组调度本身占用了约 1.25 ms/帧的发布阶段时间。带宽收益已经可见，CPU 收益需要等待 Host 直读权威表现和后续减少群组扫描工作之后再判断。

## 3. 空间索引和寻路量化

当前 10024 三次 Host 压测的四叉树统计为：

| 指标 | Repeat 1 | Repeat 2 | Repeat 3 |
|---|---:|---:|---:|
| Build 次数 | 115 | 120 | 111 |
| Build 频率 | 3.83 Hz | 4.00 Hz | 3.70 Hz |
| Build 平均耗时 | 0.964 ms | 0.950 ms | 0.946 ms |
| Query 频率 | 5.27 Hz | 5.10 Hz | 4.77 Hz |
| 平均候选数 | 34.52 | 38.71 | 41.11 |
| 候选占比 | 0.34% | 0.39% | 0.41% |

网络刷新没有把四叉树 Build 提升到每个复制 Tick。Build 频率仍由空间查询驱动，和旧 10024 参照的 4.37 Hz 同一数量级。当前网络区域码直接按根边界和四层象限计算，避免为了网络分组额外构建实体碰撞树，这一项已经通过量化数据得到支持。

10024 Host 的 FlowField 重建为 Topology 65～68 次、Source 2～7 次、Cost 0 次，约为 2.17～2.30 Hz、0.07～0.23 Hz 和 0 Hz。路径系统没有出现异常重建增长。

## 4. GC 需要单独追踪

GC 是本轮最明显的负向信号：

- 5012 Host 平均从 2,327 B/帧升到 3,406 B/帧，Client 从 1,691 B/帧升到 2,454 B/帧。
- 10024 Host 平均为 8,925 B/帧，历史参照为 2,888 B/帧。
- 10024 Client 平均为 6,460 B/帧，历史参照为 2,105 B/帧。
- 当前 10024 每次 30 秒采样触发 Gen0/1/2 各 11～17 次，旧参照只有 3～5 次。

GC 数据不能直接证明某一个新增方法造成了分配。当前应先用逐帧 `gcAllocatedBytes` 对齐长帧，再按分组生命周期、传输统计和客户端收包时间段区分启动期扩容、周期性业务分配和测试工具自身分配。需要特别观察组创建、成员表变化、`List.Sort`、网络统计字典和消息回调是否在稳定阶段仍产生托管分配。下一次压测应增加稳定期每帧 GC 的 P50、P95、最大值和 Gen0 时间，避免只看 30 秒总平均。

## 5. 当前结论和下一步量化

当前网络重构已经完成了第一项可量化目标：在 1024、2048、5012 和 10024 档位把应用层网络载荷降到旧链路的约一半到四分之三，10024 仍保持 Replica 和 VAT Slot 全量就绪。客户端群组解码和应用在 10024 三次压测中约为 `GroupApply 0.258 ms/帧`、`GroupDecode 0.095 ms/帧`，远低于旧链路的 `Presentation Apply 0.451 ms/帧` 和 `Presentation Decode 0.268 ms/帧`。

当前还不能宣布整体性能收益已经完成，因为 Host 帧时主要没有跟随网络下降，GC Alloc 在高数量级明显上升。下一轮应保持同一 Catalog 和同一 Player，优先补充以下数据：

1. 10024 至少 5 次重复，分开记录 Host `PublishGroups`、`GroupBuild`、GC 和消息数。
2. 记录每 Tick 群组数量、内中外层数量、总成员数、32 KiB 预算延期次数和最大延期 Tick。
3. 按消息名记录 `GroupMembership`、`GroupInitialSnapshot`、`GroupSnapshot` 的消息数与载荷，区分可靠首帧流量和周期 Pose 流量。
4. 在稳定运行 10 秒后单独统计 GC，确认分配来自启动扩容还是持续热路径。
5. 完成 Host 直读权威表现后，重新测量 Host `ApplyLocal`、`Publish` 和 GC，才能判断表现层去 Replica 对 Host 的实际收益。
