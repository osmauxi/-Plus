# ControlFeelTest

这是一个独立的玩家控制手感测试场景。场景不依赖正式大厅、网络会话、玩家生成流程或正式武器配置。

## 打开方式

在 Unity 中打开 `Assets/_HotUpdate/Scenes/Tests/ControlFeelTest.unity`，直接进入 Play Mode。

场景运行后会自动创建地面、测试玩家、测试靶标、灯光和程序化测试枪声。测试玩家会异步加载正式的 `Character_Gameplay_Anbi_Generic` 角色模型和 `Character_Weapon_00` 武器预制件，使用角色自身的 Animator、上半身瞄准层、枪械水平瞄准和双手 IK。急转状态和急转动画继续沿用角色现有表现。场景内已经放入正式 `GameRoot` 的镜头 Rig，测试器直接驱动正式 `PlayerCameraController`。测试副本还会把 30Hz Simulation Root 转成逐渲染帧的 Presentation Root，模型和镜头共同跟随这个渲染位姿，避免移动时出现阶梯位移和拖影。

测试启动时只保留 `GameRoot` 中的 `PlayerCameraRig`，网络、关卡、对象池和正式玩家生成服务保持停用，避免测试场景被正式流程接管。

## 操作

- `WASD` 移动
- `Shift` 冲刺
- 鼠标右键瞄准移动
- 鼠标左键开枪
- `R` 将玩家和镜头重置到起点

## 重点观察

1. 松开移动键后是否立即停止。
2. 反向输入时是否快速刹停并进入新方向。
3. 右键瞄准时是否仍能保持横移和倒退。
4. 镜头是否跟随瞄准方向产生短距离前视。
5. 模型是否随移动状态切换步态，瞄准时上半身是否快速跟随鼠标方向。
6. 开枪时是否同时触发持枪开火动画、枪械挂点、枪口闪光、程序化枪声、子弹轨迹、正式镜头 FOV 冲击和 Cinemachine 轻微后坐抖动。

基础动作状态在测试副本中会根据 Pivot、Idle、Move、Aim Move 和 Sprint Loop 直接进行短过渡，减少原始 Animator 状态机较长条件过渡带来的迟滞感。Animator 参数仍然持续驱动各状态内部的速度和方向混合。

当前测试配置已经提高三套移动模式的最大转向速度、转向加速度、转向减速度、低速响应倍率和急转制动响应，用来专门观察“正常行走转向粘滞”和“急转不明显”两个问题。正式玩家预制体的移动参数暂未改动。

测试场景的瞄准射线使用独立的稳定参考相机，参考姿态不包含瞄准前视偏移。这样可以单独观察“镜头构图”对射线和玩家朝向没有反馈放大的情况。

测试场景右键瞄准会通过正式 `PlayerCameraController` 使用 -8° FOV 修饰器，进入和退出分别使用短平滑时间。表现层直接接收每帧鼠标瞄准方向，武器水平追赶速度为 1800°/秒，上半身瞄准过渡缩短到 0.02 秒。开枪会叠加 +2.2° FOV Kick、-0.45 观察高度冲击和 Uniform/Recoil Impulse。角色表现根节点缩放为 0.82，靶标缩放为 1.8 × 3 × 1.8，碰撞体和正式移动参数不随表现比例改变。

正式子弹的权威模拟、伤害、碰撞和网络事件不由这个测试副本替换。正式武器表现使用 `WeaponPresentationService` 的对象池和 `WeaponProjectileView`，测试场景中的临时射线拖尾只用于验证即时射击反馈，不应直接作为大量子弹的正式对象创建方案。

该场景只替代网络会话和正式武器装载。移动、瞄准转向、冲刺、急停、速度曲线和固定步长直接调用正式 `PlayerSimulation` 链路，镜头跟随、瞄准构图、稳定瞄准参考相机和开枪 FOV 冲击直接调用正式 `PlayerCameraController`，测试器不再复制一套镜头规则。网络预测和服务器权威仍由正式链路执行。
